# 07 日程与任务

日程、任务 CRUD + 二次确认删除 + 软删。Agent 工具集成（Function Calling）。日程与任务共用同一套模式，差异在语义：日程面向时间点/时间段，任务面向待办状态。

## 二次确认删除（通用模式，日程/任务/文档/会话共用）

流程：第一次 `DELETE /{resource}/{id}` → **不删除**，返回 `delete_token`（Redis 存 5min）；带 token 再次请求才真删（软删）。

```python
class DeleteRequestResponse(BaseModel):
    resource_type: str
    resource_id: UUID
    delete_token: str
    expires_in: int = 300
    message: str = "再次提交以确认删除"
```

service 函数：
```python
async def request_delete(db, redis, user_id, resource_type,
                         resource_id) -> DeleteRequestResponse:
    """校验归属→生成 token→Redis `app:confirm:{user_id}:{resource_type}:{id}` 存 5min。"""

async def confirm_delete(db, redis, user_id, resource_type,
                         resource_id, token: str) -> None:
    """校验 token 匹配→软删（deleted_at=now）→写 audit（11）。失败抛 DELETE_NOT_CONFIRMED。"""
```

## Pydantic Schema

```python
class ScheduleCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200)
    description: str | None = None
    start_at: datetime
    end_at: datetime | None = None
    reminder_at: datetime | None = None

class ScheduleUpdate(BaseModel):
    title: str | None = None
    description: str | None = None
    start_at: datetime | None = None
    end_at: datetime | None = None
    reminder_at: datetime | None = None
    status: Literal["active", "cancelled"] | None = None

class ScheduleResponse(BaseModel):
    id: UUID
    title: str
    description: str | None
    start_at: datetime
    end_at: datetime | None

class TodoCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200)

class TodoUpdate(BaseModel):
    title: str | None = None
    description: str | None = None

class TodoResponse(BaseModel):
    id: UUID
    title: str
    description: str | None

    completed: bool
    created_at: datetime
```

## Service 层

### services/schedule_service.py

| 函数 | 职责 |
|---|---|
| `create_schedule(db, user_id, data) -> Schedule` | 校验时间合法性（end≥start）→ **时间重叠检测**（同用户 active 区间相交 → 08 冲突提醒）→ 建 → reminder 调 08 |
| `list_schedules(db, user_id, start_at, end_at, page_params) -> Page` | 时间范围过滤（服务端强制 user_id） |
| `get_schedule(db, user_id, id) -> Schedule` | 归属校验（带 user_id，RLS 兜底） |
| `update_schedule(db, user_id, id, data) -> Schedule` | 更新；reminder 变更同步 08 |
| `request_delete / confirm_delete` | 见上通用模式 |

### services/todo_service.py

| 函数 | 职责 |
|---|---|
| `create_todo / list_todos / get_todo / update_todo` | 同上模式 |
| `toggle_complete(db, user_id, id, completed) -> Todo` | 快捷完成/取消（工具用） |
| `request_delete / confirm_delete` | 通用模式 |

Repo：`schedule_repo`、`todo_repo`（create/update/get_by_id/list_by_user，均带 user_id 过滤）。

## Agent 工具（agent/tools.py — 07 部分）

| 工具名 | 参数 schema | 权限等级 | 职责 |
|---|---|---|---|
| `create_schedule` | ScheduleCreate | CREATE_MODIFY | 建日程 |
| `list_schedules` | {start_at?, end_at?} | READ_ONLY | 查日程 |
| `get_schedule` | {schedule_id} | READ_ONLY | 详情 |
| `update_schedule` | {schedule_id, ScheduleUpdate} | CREATE_MODIFY | 改日程 |
| `delete_schedule` | {schedule_id} | SEND_DELETE | 删除（需用户确认，见 11） |
| `create_todo` | TodoCreate | CREATE_MODIFY | 建任务 |
| `list_todos` | {completed?} | READ_ONLY | 查任务 |
| `update_todo` | {todo_id, TodoUpdate} | CREATE_MODIFY | 改任务 |
| `toggle_todo` | {todo_id, completed} | CREATE_MODIFY | 切换完成 |
| `delete_todo` | {todo_id} | SEND_DELETE | 删除（需确认） |

工具注册、参数校验、权限执行、确认流程、审计见 11。`CREATE_MODIFY`/`SEND_DELETE` 工具不直接改数据，返回"待确认动作"给用户。

## 测试要点

- CRUD 隔离：A 改 B 的日程 → 404
- 时间校验：end < start → 2001 参数错误
- 二次确认：无 token 删除不生效；错误 token 拒；token 过期拒；正确 token 软删成功且 audit 有记录
- 列表排除软删项
- Agent 工具：参数从意图提取正确映射

## 模块边界

- 提醒触发/通知：08（本模块只记 reminder_at 字段并调用注册）
- 删除审计：11
- 时间语义 vs 任务状态语义：两者实现相同，仅字段差异
