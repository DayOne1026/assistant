## 统一 HTTP 客户端（core/http_client.py）

```python
class HttpClient:
    """外部服务调用统一封装：超时 + 重试（指数退避）+ 熔断 + 降级。"""
    async def request(self, method, url, *, timeout=10, retries=2,
                      fallback=None, headers=None, json=None) -> Response | None:
        """超时 10s；失败重试 2 次（退避 0.5/1s）；仍失败走 fallback 降级；
        熔断：连续失败 5 次 → 熔断 60s（状态存 Redis），期间直接走 fallback。"""
```

## 部署

### docker-compose（环境隔离 dev/stage/prod）

```
services:
  postgres:   # pgvector 镜像，端口 5432，持久卷
  redis:      # redis:7，AOF 持久化，端口 6379
  neo4j:      # neo4j:5，数据卷，环境变量密码
  api:        # uvicorn app.main:app，依赖三存储
  worker:     # celery -A app.tasks worker
  beat:       # celery -A app.tasks beat（Beat 调度：08/10）
  flower:     # 队列监控（可选）
```

- 配置管理：`.env` + `ASSISTANT_` 前缀（01 Settings），敏感项不入库不入 git
- 健康检查：`GET /health` 依次 ping DB/Redis/Neo4j，返回 `{status, checks[]}`；compose `healthcheck` 复用
- 优雅关闭：uvicorn graceful timeout；worker `--without-gossip` 下 SIGTERM 先拒绝新任务再等当前
- 回滚：发布前 `alembic downgrade` 可行性验证 + DB 备份；先回滚代码再回滚迁移
- TLS：反代（Caddy/nginx）终结 HTTPS，强制跳转

**资源要求与运行前提**：
- Neo4j 容器建议 ≥4GB 内存；PG/Redis 轻量
- CLIP（06 图片库）：首次调用下载模型（~几百 MB，sentence-transformers 缓存），需网络/梯子
- LLM/embedding 走 API（DeepSeek/千问 key，01 Settings）；前端 dev 走 vite proxy，生产 Nginx 反代（13）

## 数据工程与运维

| 事项 | 方案 |
|---|---|
| 迁移 | Alembic；schema diff 走 review；迁移前 `assert_rls_enabled` 自检（03） |
| 备份 | PG `pg_dump`（每日）+ WAL 归档；Neo4j `neo4j-admin dump`；Redis AOF |
| 索引优化 | 慢查询日志 → EXPLAIN → 补索引；chunks hnsw（06） |
| 数据归档 | 软删 >30 天物理清除（Celery purge 任务）；审计日志保留策略（如 180 天） |
| 队列积压 | Flower + Redis list 长度指标；超过阈值告警 |
| 依赖漏洞 | 依赖扫描（pip-audit）入 CI |
| 用户数据导出/删除 | `/account/export`（打包偏好+图谱+文档）、`/account` 注销级联删除（02 级联） |
