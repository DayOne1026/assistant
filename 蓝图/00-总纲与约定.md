# 00 总纲与约定

## 项目定位

多用户 AI 私人助理平台，用于求职展示。核心展示工程化能力、AI Agent 编排、数据架构与安全实践。
本蓝图覆盖 1.md（项目总结）全部模块，不降级。

## 架构分层

```
┌─ 接入层：FastAPI REST + WebSocket + MCP server
├─ 应用层：认证、用户、对话、日程、任务、通知、集成、审计 API
├─ Agent 引擎：LangGraph（意图路由/对话/Skill 子图）+ Function Calling 工具 + 工具安全层
├─ 业务层：各 Service（校验、编排、策略）
├─ 数据层：Repo（PG/Redis/Neo4j 访问）
└─ 存储：PostgreSQL(pgvector) + Redis + Neo4j
```

- 异步任务：Celery + Celery Beat（提醒、规则、RAG 索引、外部同步）
- 实时推送：WebSocket（即时提醒、通知）

## 全局约定

### 统一响应

成功：`{ "code": "0", "data": {...}, "message": "ok" }`
失败：code 为错误码，data 为 null 或错误详情。
所有响应经 `ApiResponse` 包装（01）。

### 错误码段

| 段 | 含义 |
|---|---|
| 1000-1999 | 认证（token 无效/过期、密码错误、账户锁定） |
| 2000-2999 | 参数校验、幂等冲突 |
| 3000-3999 | 权限/隔离违规 |
| 4000-4999 | 资源不存在、业务状态冲突 |
| 5000-5999 | 服务不可用、外部依赖失败 |

枚举 `ErrorCode` 定义见 01，全表见 12。

### 命名约定

- 数据库表：snake_case 复数；SQLAlchemy 模型：PascalCase 单数
- Pydantic 入参：`XxxCreateRequest` / `XxxUpdateRequest` / `XxxQuery`；出参：`XxxResponse`，列表 `XxxListResponse`
- Service 方法：`动词_名词`（`register_user`、`confirm_delete`）；Repo 方法：`create/update/get/list/delete` + 实体
- Agent 工具名：snake_case（`create_schedule`）
- 一律 `async def`；DB/Redis 用异步驱动

### 分页

入参 `page`（默认1）+ `page_size`（默认20，上限100），返回 `Page`：`{items, total, page, page_size}`。

### 时区

一律 UTC 存储，响应时转 `users.timezone`。

### 审计

所有写操作（增删改、工具调用）写 `audit_logs` / `tool_call_logs`，见 11。

### 工具权限等级

```python
class ToolLevel(str, Enum):
    READ_ONLY = "read_only"        # 直接执行
    CREATE_MODIFY = "create_modify"  # 用户确认后执行
    SEND_DELETE = "send_delete"    # 二次确认
    HIGH_RISK = "high_risk"        # 禁止注册
```

### 数据隔离三件套

- PG：RLS（03）
- Neo4j：业务节点带 `user_id` 属性 + 查询强制条件（03）
- Redis：key 前缀 `{scope}:{user_id}:...`（03）

### 依赖版本（锁定）

Python 3.11 / fastapi 0.111 / sqlalchemy 2.0 / asyncpg / alembic / pydantic 2.7 / pydantic-settings / redis-py 5 / neo4j 5 / langgraph 0.2 / langchain 0.2 / langchain-community / celery 5 / pgvector / opentelemetry

LLM：默认 DeepSeek（`langchain_community.chat_models.ChatDeepSeek`），可切千问（`ChatTongyi`，DashScope）。模型名、base_url、api_key 走配置（01）。
