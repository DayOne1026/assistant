## Service 层（services/integration_service.py）

```python
class IntegrationService:
    def __init__(self, db, redis): ...

    async def start_oauth(self, user_id, provider, redirect_uri) -> AuthUrlResponse:
        """生成 state → Redis 存 `app:oauth:state:{user_id}:{state}`（TTL 10min）→ 返回 url。"""

    async def complete_oauth(self, user_id, provider,
                             data: OAuthCallbackRequest) -> Integration:
        """校验 state → 换 token → 加密存库（upsert by provider+account）→ 撤销旧。"""

    async def get_access_token(self, user_id, integration_id) -> str:
        """解密；过期则自动刷新并回写。失败抛 INTEGRATION_INVALID。"""

    async def revoke(self, user_id, integration_id) -> None:
        """调 provider.revoke → 置 revoked_at。"""
```

`complete_oauth` 伪代码：
```
stored = await redis.get(redis_key("oauth", user_id, data.state))
if not stored or stored != provider: raise INTEGRATION_INVALID
tok = await PROVIDERS[provider].fetch_token(data.code, redirect_uri)
row = upsert(user_id, provider, tok)          # 加密 token 后写入
await redis.delete(redis_key("oauth", user_id, data.state))
return row
```

`get_access_token` 伪代码：
```
row = get_integration(user_id, integration_id)   # 带 user_id 过滤
if row.revoked_at: raise INTEGRATION_INVALID
token = decrypt_token(row.access_token_enc)
if row.expires_at and row.expires_at < now + 60s:      # 提前 60s 刷新
    new = await PROVIDERS[provider].refresh(decrypt(row.refresh_token_enc))
    row.access_token_enc = encrypt(new.access_token); row.expires_at = ...; commit
    return new.access_token
return token
```

## MCP 连接（integrations/mcp_client.py）— 复用 `zhao/mcp/client.py`

完整 JSON-RPC 2.0 客户端，**双传输**（stdio 子进程 + Streamable HTTP），Lifecycle → Tools → Resources → Prompts 四块完整实现。

```python
class MCPError(Exception):
    """JSON-RPC 错误：code + message（-32700 解析/-32601 方法不存在/-32000 超时等）。"""

class MCPClient:
    def __init__(self, transport="stdio", command=None, args=None, env=None, url=None):
        """stdio：subprocess.Popen(stdin/stdout/stderr, text)，后台线程读 stdout
        http：后台 GET 建 SSE 流收推送，POST 发请求（Mcp-Session-Id 会话）"""
```

| 方法 | 职责 |
|---|---|
| `initialize()` | 握手：协议版本(2025-06-18) + capabilities，发 `notifications/initialized` |
| `shutdown()` | 优雅关闭：http 请求 shutdown；stdio 通知 + terminate |
| `list_tools()` / `call_tool(name, arguments)` | 工具发现与调用 |
| `register_all(registry)` | 把 server 所有工具注册进 11 ToolRegistry |
| `list_resources()` / `read_resource(uri)` | Resources 块 |
| `list_prompts()` / `get_prompt(name, args)` | Prompts 块 |
| `_request(method, params)` | JSON-RPC 内核 |

**JSON-RPC 内核要点**（复用 zhao 线程模型，原样搬）：
```
- stdio：后台线程 _read_loop 逐行读 stdout，按 id 唤醒等待线程（_pending: id→Event）
- http：后台线程 _sse_loop 建 SSE 流收推送；POST 返回 202 → 等 SSE 推送匹配 id
- 线程安全：_lock 保护 _pending/_results；_send_lock 防 stdin 写交错
- 无 id 的通知消息直接忽略；60s 超时抛 MCPError(-32000)
```

`register_all` 伪代码：
```
for t in self.list_tools():
    registry.register(ToolDef(
        name=t["name"], description=t.get("description", ""),
        parameters_schema=t.get("inputSchema", {"type": "object"}),
        level=ToolLevel.CREATE_MODIFY,        # 外部副作用默认确认级，可配置覆盖
        handler=make_async_handler(self, t["name"])))
```

`make_async_handler(client, name)`：`async def handler(user_id, params): return await asyncio.to_thread(client.call_tool, name, params)`。
> lambda 里不能 `await`，而 ToolDef.handler 类型是 `Awaitable`——必须用 async def 工厂。
```

**适配点**（zhao 同步 → 蓝图 async）：
- zhao MCPClient 是同步线程模型：**保留线程模型**，async 侧 `await asyncio.to_thread(client.call_tool, ...)` 包一层（线程模型天然处理并发响应，不建议改异步）
- `register_all` 绑定蓝图 `ToolRegistry`（11），不绑定 zhao 的 Tool
- 配置来源：`mcp_servers` 表（按用户存 transport/command/args/url）→ 启动时实例化并 register_all

## 测试要点（MCP）

- stdio 起一个本地 MCP server（如 tavily）→ list_tools 返回工具 → call_tool 正常
- http 模式 SSE 推送匹配 id；202 异步响应能唤醒
- register_all 后工具进 ToolRegistry，权限等级生效、调用被审计（11）
- 超时/连接失败抛 MCPError，不挂起
