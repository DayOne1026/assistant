# 03 数据隔离

多用户强制隔离三件套：PG RLS（行级）、Neo4j `user_id` 属性 + 查询强制、Redis key 前缀。
原则：**fail-closed**——配置缺失/未显式带 user_id 时一律查不到数据。

## PostgreSQL RLS

### 迁移（alembic 每个业务表一份）

```python
def upgrade():
    op.execute("ALTER TABLE schedules ENABLE ROW LEVEL SECURITY")
    op.execute("""
        CREATE POLICY schedule_user_isolation ON schedules
        USING (user_id = current_setting('app.current_user_id')::uuid)
        WITH CHECK (user_id = current_setting('app.current_user_id')::uuid)
    """)
```

说明：
- `USING` 管 SELECT/UPDATE/DELETE，`WITH CHECK` 管 INSERT/UPDATE。
- 未设置 `app.current_user_id` 时 `current_setting` 抛错或返回 NULL → 全部行不可见。**fail-closed**。
- 每张带 `user_id` 的业务表都需 `ENABLE ROW LEVEL SECURITY`（迁移清单：schedules、todos、conversations、messages、user_preferences、documents、document_chunks、skills、automation_rules、user_integrations、refresh_tokens 不适用 RLS，走应用层过滤）。

### 请求级上下文设置

```python
async def set_tenant_context(session: AsyncSession, user_id: UUID) -> None:
    """在事务内设置 RLS 用户上下文。必须在任何业务查询前调用一次。"""
    await session.execute(
        text("SELECT set_config('app.current_user_id', :uid, true)"),
        {"uid": str(user_id)})

async def clear_tenant_context(session: AsyncSession) -> None:
    """事务结束后清理，防连接复用串号（set_config local=true 事务自动清，兜底显式清）。"""
    await session.execute(text("SELECT set_config('app.current_user_id', '', true)"))
```

- `set_config(..., true)` 第二参 `is_local=true` = `SET LOCAL`，事务结束自动失效，杜绝连接池串号。
- 统一入口：`get_current_user_isolated` 依赖（02）在路由层调用 `set_tenant_context`。
- 兜底：Service 层查询仍显式带 `user_id` 过滤（双保险，见 07-10 所有 repo）。

## Neo4j 隔离

### 节点/关系约定

业务节点标签：`Person, Place, Organization, Topic, Event, Document`。
每个业务节点必须带 `user_id`（String）属性。

关系（均在同一 user_id 内部）：`KNOWS, WORKS_AT, LIVES_IN, LIKES, RELATED_TO, MENTIONS`。

### 约束（迁移）

```cypher
CREATE CONSTRAINT person_unique IF NOT EXISTS
FOR (n:Person) REQUIRE (n.id, n.user_id) IS UNIQUE
-- 对所有业务标签重复（Place/Organization/Topic/Event/Document）
```

复合唯一 `(id, user_id)` 保证同一用户内节点 id 唯一，且 user_id 参与唯一性。

### 查询强制 user_id

```python
def neo4j_user_scope(user_id: UUID) -> dict:
    """业务 Cypher 必须使用该参数做首条过滤。"""
    return {"user_id": str(user_id)}
```

约定（code review 必查项）：所有业务 Cypher 首行 `WHERE n.user_id = $user_id`，禁止裸 `MATCH`。

`Neo4jClient.verify_user_scope(user_id, node_id, label)`（01）：
```cypher
MATCH (n:`{label}`)
WHERE n.id = $node_id AND n.user_id = $user_id
RETURN n LIMIT 1
```
写操作（UPDATE/DELETE/建立关系）前一律先 `verify_user_scope`，失败抛 `ISOLATION_VIOLATION`。

## Redis key 前缀

```python
def redis_key(scope: str, user_id: UUID, *parts: str) -> str:
    """统一 key 规范：app:{scope}:{user_id}[:part...]。"""
    return ":".join(["app", scope, str(user_id), *parts])
```

已用 key 规范：
| scope | key | TTL | 用途 |
|---|---|---|---|
| session | `app:session:{user_id}:{conversation_id}` | 会话 | LangGraph checkpointer（04） |
| ratelimit | `app:ratelimit:{user_id|ip}:{route}` | 窗口 | 限流（11） |
| jwt | `app:jwt:blacklist:{jti}` | access 剩余 | 黑名单（02） |
| lock | `app:lock:{user_id}:{resource}` | 10s | 分布式锁 |

所有模块禁止裸 key，一律 `redis_key(...)` 生成。

## 隔离验证（测试清单）

1. **RLS SQL 层**：直接连 DB 以 user A 上下文查 schedules，确认只返回 A 的数据；无上下文查询返回空（fail-closed）。
2. **API 层**：A 的 token 请求 B 的 `/schedules/{b_id}` → 404/403，不得泄漏"存在"。
3. **Neo4j 层**：`verify_user_scope(A, B 的节点)` → False；B 节点不在 A 的查询结果。
4. **Redis 层**：A 的会话 key 与 B 完全隔离；断言 key 含 A 的 user_id 前缀。
5. **未配置自检**：`assert_rls_enabled` 对全表通过（迁移完成后）。

## 防绕过设计

- RLS 是**兜底**不是唯一防线：Service 层显式过滤 + RLS 双保险（任一失效仍有第二道）。
- RLS 未设置上下文 = 查不到 = 安全默认。
- Neo4j 复合唯一约束 + verify_user_scope 强制归属校验。
- Redis key 含 user_id，无跨用户枚举面。
